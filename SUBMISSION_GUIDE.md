# Telecom RAG — Final Assignment Submission Guide

This walks through the three deliverables: Docker, one executed RAG
request + cost report, and the CI workflow. The CI file
(`.github/workflows/ci.yml`) and the cost calculator
(`calculate_cost.py`) are already added to this repo — you just need
to run the steps below on your own machine (they need your real
`GOOGLE_API_KEY` and internet access, so they can't be run from a
sandboxed assistant on your behalf).

## 1. Dockerize the application

The repo already has a working `Dockerfile` at the root. Build and run it:

```bash
# 1. Put your real key in .env (never commit this file — it's already gitignored)
cp .env.example .env
# edit .env and set GOOGLE_API_KEY=your_actual_key

# 2. Build the image
docker build -t telecom-rag:latest .

# 3. Run the container, mounting .env so the key is available inside
docker run -d --name telecom-rag -p 8000:8000 --env-file .env telecom-rag:latest

# 4. Confirm it's up
curl http://localhost:8000/
```

Expected health-check response:

```json
{"status": "healthy", "app_name": "Telecom RAG API", "version": "1.0.0", "docs_url": "/docs"}
```

Swagger UI is at `http://localhost:8000/docs`.

## 2. Execute one RAG request

The vector index has to be built once before `/api/v1/query` will
work — the app returns 404 until you've ingested a document.

**Step A — Ingest the sample knowledge base:**

```bash
curl -X POST http://localhost:8000/api/v1/ingest \
  -F "file=@data/Telecom_Internal_KB.txt"
```

**Step B — Run the RAG query:**

```bash
curl -X POST http://localhost:8000/api/v1/query \
  -H "Content-Type: application/json" \
  -d '{"ticket": "النت فاصل عندي ولمبة DSL بتنور وتطفي"}'
```

The response will look like this (your `response` text and token
counts will vary run to run):

```json
{
  "ticket": "النت فاصل عندي ولمبة DSL بتنور وتطفي",
  "response": "<Arabic customer-support reply generated by Gemini>",
  "sources_count": 20,
  "execution_time_seconds": 2.1,
  "prompt_tokens": 1850,
  "completion_tokens": 210,
  "total_tokens": 2060
}
```

**Save both the request and this exact response JSON** — that's your
"request + response as evidence" deliverable. A screenshot of the
Swagger UI (`/docs`) executing the request also works well as
evidence.

## 3. Calculate and report the cost

The response already includes `prompt_tokens` and `completion_tokens`,
which is exactly what's needed to price the call. Gemini 2.5 Flash
(the model set in `config/config.yml`) is billed per token on the
standard paid tier:

| | Price per 1M tokens |
|---|---|
| Input (prompt) | $0.30 |
| Output (completion) | $2.50 |

*(Source: [Gemini Developer API pricing](https://ai.google.dev/gemini-api/docs/pricing), verified August 2026 — check that page for the current rate before submitting, since Google updates pricing periodically.)*

Cost formula:

```
input_cost  = (prompt_tokens     / 1,000,000) * 0.30
output_cost = (completion_tokens / 1,000,000) * 2.50
total_cost  = input_cost + output_cost
```

Run the included helper with your actual numbers from Step B:

```bash
python calculate_cost.py --prompt-tokens 1850 --completion-tokens 210
```

Example output for those numbers:

```
=== Gemini 2.5 Flash Cost Estimate ===
Prompt tokens:     1850
Completion tokens: 210
Total tokens:      2060
Input cost:        $0.00055500
Output cost:       $0.00052500
Total cost:        $0.00108000
```

So a single query costs roughly a tenth of a cent — the retrieval
step (FAISS, `k_retrieval: 20` in `config.yml`) pulls in a lot of
context, which is most of the input token cost; the output is a
short Arabic reply, which keeps the output cost low.

Report this table in your submission with your **actual** numbers
from the real response, not the example above.

## 4. CI with GitHub Actions

`.github/workflows/ci.yml` is already added. It:
- Triggers on every `push` and `pull_request` to any branch.
- Installs `requirements.txt`.
- Sets a `GOOGLE_API_KEY` env var (from a repo secret if you add one
  under Settings → Secrets → Actions, otherwise falls back to a dummy
  value — fine for CI since the tests mock the LLM call and don't hit
  the real API).
- Runs `pytest -v --maxfail=1`, which fails the workflow on any test
  failure.

Once you push this to GitHub, check the **Actions** tab to confirm it
runs and passes.
